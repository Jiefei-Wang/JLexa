## Native OpenCL evidence

Pixel exposes Mali-G78 OpenCL 3.0 with FP16 and subgroup support. Standalone FP32, FP16 and subgroup probes passed. Adapted Q4_K/Q6_K matrix kernels passed 12 CPU-reference comparisons (K=256/1024/4096; shapes 8×1 and 64×7; maximum scaled error below 4.4e-5). Real Qwen2.5 0.5B arithmetic, Chinese translation, say/tell explanation, repeated requests, cancellation after five tokens, next-request recovery and unload/reload passed in the isolated runtime.

Controlled fixture times on this model/device, seconds (not a general performance ranking):

| Backend | Short warm request | Long prompt | 69-token generation |
| --- | ---: | ---: | ---: |
| CPU | 0.65 | 9.29 | 2.52 |
| Restricted OpenCL | 0.75 | 9.45 | 4.89 |
| Vulkan | 2.56 | 20.20 | 7.83 |

Only supported Q4_K/Q6_K matrix multiplication runs on GPU; other operations and KV cache stay on CPU. This model also contains Q5_0/Q8_0 weights, so the accelerator scope is partial. Settings explicitly identify the experimental mixed runtime and possible slowdown. The signed app successfully loaded OpenCL through Android's app namespace and generated a Chinese answer. Missing-library/API behavior is covered by isolated concurrent loader tests, since this Pixel actually provides the library.

## Second fresh review

A second independent reviewer checked the resulting Home, Dictionary, Listening, Chat and Study source and representative captures. Three further issues were accepted and fixed: post-split Previous/Next follows the explicitly selected left cut even after a late decoder callback; Android's first microphone permission dialog retains the pending request until resume, while hidden/paused still cancels it; English pronunciation resets the shared Android TTS language after Chat speaks Chinese and rejects disposed/superseded speech requests. Dedicated regressions cover each. The first-permission defect was also reproduced on Pixel before the fix; leaving a recording through the bottom navigation stopped capture and returned idle.

A fresh Settings review also found and fixed shared SAF event-channel interference, premature cancellation subscription disposal, duplicate download ownership, folder changes during finalization, failed provider deletion reporting and same-name/different-folder identity. Native terminal events now follow stream closure. Settings displays per-model errors and Cancelling state; CPU thread dragging applies only the final value on release. The slider regression proves exactly one reload with that value.

Shared native Whisper ownership is now protected at the Dart bridge: a competing chat transcription cannot replace Listening's request ID, progress callback, completion slot or cut bounds. Cancellation retains ownership until native terminal completion; model changes wait for that completion. Six channel-level tests cover these overlaps and cancellation/error paths.

## Deliberate limits

- OpenCL is restricted to the numerically tested Mali-G78 operations. A generic GPU-family port would require substantially more kernels, scheduler paths and device coverage; it is not enabled speculatively.
- Model quality and acoustic segmentation remain imperfect. The installed Qwen2.5 0.5B gave an inaccurate claim that tell is mainly more formal/technical than say in the final Vulkan chat sample. It did correctly explain Hello in Chinese. Successful generation and numerical backend correctness are not guarantees of teaching accuracy. Existing manual boundaries and explicit regeneration remain available.
- Multi-step segment undo was not added in this pass: restoring historical cut revisions together with invalidated/in-flight transcript ownership needs a separate design. Persisted edits, manual recovery and explicit confirmed Redo remain the supported workflow.
- Unload frees model RAM while preserving the startup selection; the selected model is restored on next launch.
- Tests used supplied/synthetic audio and brief microphone capture/cancellation. No claim of real conversational microphone recognition accuracy is made without supplied speech.

Artifacts are captured under the untracked `artifacts/pixel-ux/` working directory; selected evidence is copied to `docs/images/`. Failed/null UI dumps are rejected by the capture helper to avoid mistaking an older snapshot for current device state. Raw database snapshots remain untracked.
